# 论文速读：Complex-Claim-Verification-with-Evidence-Retrieved-in-the-Wi

## 一句话总结
本文提出了首个面向真实场景的复杂政治声明自动核查流程，通过时间约束和站点约束从网络检索声明发布时已有的原始证据，结合声明分解、两阶段检索、LLM聚焦摘要与分类器，显著提升了声明真实性判断的准确率。

## 研究问题与动机
- **现有系统依赖不现实前提**：以往自动事实核查系统要么仅依赖声明本身（缺乏证据），要么假设能访问由人工核查员预先整理的"黄金证据"集合，无法反映真实核查场景。
- **无约束检索存在事后偏差**：开放网络检索经常返回声明发布后才出现的事后核查文章（如 PolitiFact 等站点本身的内容），造成信息泄漏，且不能代表声明发出时实际可获得的信息。
- **实时核查场景缺乏系统性方案**：面对新兴声明，如何在声明发布时即能获取的证据范围内开展核查，尚缺少端到端可行的自动化流程。
- **仅凭分类准确率不足以评估系统效用**：六分类判断具有主观性，需结合中间输出（摘要）的忠实度和覆盖度来综合评估系统的实际辅助价值。

## 核心贡献（创新点）
1. **首个真实检索约束下的端到端事实核查流程**：提出包含声明分解→原始文档检索→细粒度证据检索→声明聚焦摘要→真实性分类的五阶段流水线，与以往工作或依赖预标注证据、或无约束检索的本质区别在于同时施加了时间约束（仅检索声明发布前的文档）和站点约束（排除事实核查网站）。
2. **基于子问题的两阶段检索策略**：用 LLM 将复杂声明分解为 10 个 yes/no 子问题驱动第一阶搜索，再用 BM25 在第一阶文档中召回 Top-K1 文本段并扩展上下文进行第二阶检索，相较直接使用原始声明检索，显著提升可检索到的相关文档数量与质量。
3. **引入软准确率（soft Acc）与忠实度/覆盖度联合人工评估**：在六分类尺度上允许差一级的预测算正确，同时通过 MTurk 人工评估摘要的事实忠实度与对子问题的可回答性，弥补单一自动指标对主观判断场景的不足。
4. **实证揭示真实约束下检索的核心挑战**：通过放宽/收紧检索约束的对比实验发现，不加约束时高达 82.7% 的命中文档来自被排除的站点，说明 prior work 在无约束设置下的性能很大程度上受益于"事后核查文章"；在严格约束下，仍需大量证据无法获取（约 36% 子问题无法回答）。

## 方法详解
整个流水线共五阶段：

1. **声明分解（Claim Decomposition）**：使用 text-davinci-003 配合 4 个 in-context 示例进行 few-shot 提示，对每条复杂声明采样生成 10 个 yes/no 子问题（覆盖显式与隐式维度），并通过字符串去重消除重复。
2. **第一阶段检索（First-stage Retrieval）**：将每个子问题提交至 Bing Search API，施加两个约束——时间约束（仅保留声明发布前发表的页面）和站点约束（排除 PolitiFact、Snopes、FactCheck.org 等事实核查站点），每个子问题取 Top-10 文档；使用 html2text 和 readability-lxml 提取页面正文，约 1/3 的 URL 因反爬无法抓取。
3. **第二阶段检索（Second-stage Retrieval）**：将第一阶段获得的文档切分为 k1=30 词的文本段（步长 15 词），使用 BM25 检索 Top-K1=10 个得分最高的文本段，再以 ±k2=150 词上下文进行扩展；重叠文本段合并为更大片段，最终选取 Top-K2=4 个文档。
4. **声明聚焦摘要（Claim-Focused Summarization）**：针对每份检索文档，分别用 zero-shot 或 few-shot prompt 提示 text-davinci-003 生成 1-2 句声明相关摘要（要求不作立场判断），few-shot 方式在人工评估中表现出更低的事实错误率。
5. **真实性分类（Veracity Classification）**：将声明与摘要拼接后输入至 DeBERTa-large 分类器，进行六分类（true / mostly true / half true / barely true / false / pants-on-fire）；由于数据量小（800 条训练集），采用 5 次不同随机种子的训练并在开发集上选取 MAE 最优模型，测试集报告其性能。

**关键超参**：k1=30、k2=150、K1=10、K2=4、batch_size=32、lr=3e-5、max_seq_len=512、epochs=25。

## 实验与结果
- **数据集**：CLAIMDECOMP（Chen et al., 2022a），包含 1,200 条来自 PolitiFact 的复杂政治声明（train: 800 / dev: 200 / test: 200），每条含六类真实性标签及人工专家撰写的论证段落与子问题标注。
- **评估指标**：Accuracy、Soft Accuracy（允许差一级的预测判为正确）、Macro-F1、Mean Absolute Error（MAE，在 6 点尺度上）。
- **最强结果**：默认系统（full pipeline + 时间与站点约束）在测试集上达到 **Acc=33.0%**、**Soft Acc=74.5%**、**Macro-F1=34.5%**、**MAE=0.99**，相较 Claim-only 基线（Acc=25.5%，p<0.05 显著）有明显提升。
- **各阶段消融**：使用生成的子问题做第一阶段检索比直接用原始声明（Acc 24.5%）提升显著；使用 few-shot 摘要（Acc 35.0%）略优于 zero-shot（Acc 33.0%）；不做摘要直接喂原始文本段（Acc 29.0%）表现最差，说明摘要压缩关键。
- **检索稳定性**：以相隔 1 周和 2 个月重复检索，URL Jaccard 分别为 0.48 和 0.30，但下游分类指标无显著变化（Soft Acc 仍维持在 73.5%–74.0%），说明分类结果对搜索引擎结果的时序波动具有一定鲁棒性。
- **约束 vs 无约束对比**：去除时间/站点约束（类比 MultiFC 设置）可使 Acc 升至 49.0%，但其中 82.7% 的召回文档会被本文排除，说明 prior work 的"高性能"很大程度上受益于事后核查文章。
- **人工评估**：在 50 条声明、200 对文档-摘要样本上，few-shot 摘要的忠实度评价中 89% 达到"Faithful + Minor"水平；覆盖度评估中，few-shot 摘要能部分回答 60%+ 的 Gold 子问题；但在 50 条声明中仍有 36 条至少包含 1 个无法回答的子问题，印证"在野外充分检索证据是核心挑战"这一结论。

## 相关工作脉络
1. **早期无证据核查（Vlachos & Riedel, 2014; Wang, 2017）**：仅以声明本身输入模型，依赖表层语言模式判断，未引入外部证据检索；本文在此基础上引入真实检索环节。
2. **预标注证据的多文档事实核查（FEVER 系列; Hanselowski et al., 2019; Atanasova et al., 2020）**：假设系统可访问人工标注的"黄金证据"集合；本文强调该设定在真实场景中不可得，转而面向开放网页检索。
3. **无约束网络检索（MultiFC, Augenstein et al., 2019）**：使用 Google Search API 无时间/站点限制地召回证据，文中 82.7% 召回结果会被本文的站点约束排除，本文指出这种设置高估了真实场景性能。
4. **问题生成辅助检索（Fan et al., 2020; Sachan et al., 2022）**：通过生成 wh-questions 检索网页，但依赖人工过滤或仅评估到检索层面；本文进一步将 yes/no 子问题贯穿至检索、摘要与分类全流程，并施加时间/站点双重约束。
5. **实时 Web 核查数据集 AVeriTeC（Schlichtkrull et al., 2023）**：与本文同期提出使用真实声明和从网络检索的证据，但其问题是 wh-questions 而非本文使用的二元 yes/no 子问题，且未施加时间约束；本文强调其子问题设计能更全面覆盖声明的显式与隐式事实维度。
6. **检索增强生成（RAG 系列, Lewis et al., 2020; Nakano et al., 2021/WebGPT）**：将检索作为增强手段用于问答与生成；本文将其引入事实核查领域并强调约束性检索的真实场景意义，同时指出 LLM 作为分类器直接消费摘要时反而性能下降（附录 D），凸显领域适配的重要性。

## 局限性与未来方向
- **检索成功率为核心瓶颈**：约 36% 的子问题在任何摘要下均无法回答，其中一部分源于网上除事实核查站点外无其他可用信息（如涉及具体个人的事实），另一部分源于生成的子问题质量不足或未能完成去上下文化（decontextualization）。
- **人机协作机制尚未落地**：作者设想系统应输出摘要与初步判断，供人类核查员审核；若核查员认为证据不充分，可反馈以重新调整检索问题并迭代，系统可进一步从反馈中学习，但目前仅提出设想，未实现。
- **语言与领域局限**：当前只处理英文政治声明，其他语言及社交媒体图文/梗图类声明尚未覆盖。
- **搜索 API 的可复现性问题**：商业搜索引擎结果随时间波动（2 个月间隔仅有 30% URL 重合），不利于长期稳定评测，作者呼吁构建公开、稳定、具挑战性的基准文档集。
- **LLM 作为分类器的陷阱**：附录 D 显示直接用 ChatGPT 做分类在加入摘要后性能反而下降，可能源于模型过度依赖自身参数化知识而无法有效利用给定摘要，说明领域内微调仍有必要。

## 研究启发与可借鉴点
1. **声明/问题分解作为检索质量放大器**：将复杂声明拆解为多个 yes/no 子问题分别检索，远比单条原始声明检索更能覆盖不同事实维度；这一策略可迁移至复杂 QA、法律/医学文献综述等需多源证据支持的任务。
2. **时间约束与站点约束对评测效度的关键作用**：在面向实时核查或证据时效敏感的任务中，必须对检索窗口做约束；否则评测结果会严重高估真实可用性。这一设计原则适用于任何"证据来自开放网络"的下游任务。
3. **Few-shot 提示在检索聚焦摘要中对忠实度的显著提升**：本文证明 few-shot 示例能大幅降低 LLM 生成摘要的事实错误（89% 达到可用水平），且在不需要精确查询词的粗粒度检索后，摘要忠实度尤为重要，可作为检索→生成链路中质量控制的标准做法。
4. **软准确率（soft Acc）作为主观判断任务的替代指标**：当标签本身具有主观连续尺度时，允许"差一級"的正确判定更能反映系统实用性；可与 MAE 配合使用，避免单一硬 Acc 误判系统价值。
5. **检索稳定性评估应纳入实验设计**：通过多轮重复检索并报告 URL 重叠与下游指标稳定性，可为后续工作提供基准可比性；建议在未来基于商业搜索引擎的工作里常规报告该分析。

## 关键术语表
**Claim Decomposition（声明分解）**：将一条复杂政治声明拆解为多个 yes/no 子问题的过程，用于覆盖声明的显式与隐式事实维度，辅助后续检索。
**Temporal Constraint（时间约束）**：要求检索到的文档发布日期早于声明发布时间，模拟声明发出时即可获取的证据范围。
**Site Constraint（站点约束）**：排除来自已知事实核查网站（如 PolitiFact、Snopes 等）的文档，避免使用事后合成的核查内容。
**Claim-focused Summarization（声明聚焦摘要）**：针对特定声明，让 LLM 从检索到的单个文档中抽取 1-2 句相关内容摘要，要求保持忠实且不作出立场判断。
**Soft Accuracy（软准确率）**：在六分类真实性尺度上，将与实际标签相差一级的预测（如把"mostly true"判为"half true"）也算作正确的评估指标。
**Decontextualization（去上下文化）**：将嵌入在原声明语境中的子问题改写为能独立理解的问句，使检索引擎无需依赖原始上下文即可匹配相关文档。
**CLAIMDECOMP**：Chen et al. (2022a) 构建的数据集，包含 1,200 条 PolitiFact 复杂政治声明，附六分类标签、人工论证段落及 yes/no 子问题标注。
**Human-in-the-loop Fact-checking（人机协作事实核查）**：系统将自动化检索与摘要作为辅助，由人工核查员审核、反馈并迭代优化证据获取流程的新型核查范式。

## 可复现要素
- **数据集**：CLAIMDECOMP（Chen et al., 2022a）——论文未明确声明开源状态，据查该数据集在发布方页面可获取。
- **代码**：论文未开源代码与权重。
- **关键超参**：k1=30（文本段长度）、k2=150（上下文扩展宽度）、K1=10（BM25 召回段数）、K2=4（最终文档数）、batch_size=32、lr=3e-5、max_seq_len=512、epochs=25、5 次随机种子取 dev 最优。
- **模型**：text-davinci-003（GPT-3.5 davinci）用于声明分解与摘要生成；DeBERTa-large 用于真实性分类；Bing Search API 用于第一阶段检索。
- **其他**：html2text 与 readability-lxml 用于页面内容提取；部分 URL 因反爬机制无法抓取（约 1/3）。
